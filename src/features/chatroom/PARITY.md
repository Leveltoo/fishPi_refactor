# 聊天室交互对照

只补了旧客户端里还缺的聊天室交互。配色、字体、侧栏和气泡样式没有改。

## 做了什么

- 天气消息按 payload 里的地区、描述、逐日最高/最低温和天气代码渲染卡片。图标只用本目录已有的 svg；缺字段就留空，整卡没有数据时退回摘要。
- 音乐消息渲染歌名、来源和封面。`source` 里能解析出网易云 `id=` 时，用和旧客户端相同的 `music.163.com/song/media/outer/url` 交给 `HTMLAudioElement` 播放这一首。没有地址就只显示歌名，并写明未在播放。
- 表情：默认短码来自旧 `fishpi@0.0.59` 的 `emoji.default`，点选往输入框插入 `:name:`。服务器分组、分组内表情、按 URL 添加和删除走 SDK 1.1.0 的 `emoji()`，成功才提示已同步。最近使用存在本机 `chatroom-filters.json` 的 `emojiRecent`，不写成服务器收藏。
- 连续相同正文按旧 `mergeDoubleMsg` 收成一条，后面的人显示头像和「也这么说」。+1 只出现在最后一条非红包消息已经有人跟说时，点击走现有 `chatroom_send` 重发这条正文。
- 修改话题走现有发送命令，正文是 `[setdiscuss]话题[/setdiscuss]`，最长 16 个字符。空话题不能发。
- 弹幕用消息自带颜色写在正文上。颜色在 Bridge 里过滤，前端再挡一层，拒绝 `url` / `expression`。旧版 +1 不会出现在弹幕上（弹幕不进合并），这里同样不给弹幕单独的 +1。`chatroom_barrager` 已接上 SDK，但界面没有新的发弹幕入口。
- 发言来源用短文字标在名字旁边（网页、手机、IDE、桌面等），悬停可看客户端和版本。
- 聊天室顶栏有「屏蔽」。规则类型与旧 `shieldType` 一致：用户、内容正则、红包。特别关心要先对上 `user_profile` 的用户名。规则存在 `chatroom-filters.json` 的 `chatroomFilters`，不写 token 或密码。被关心的用户名字旁有「关心」标记。
- 红包仍是原来的可点击摘要，继续派发 `fishpi:redpacket`，没有退回普通文本。

## SDK 没有，所以没做

- 旧客户端自定义表情包走 `api/cloud` 的 `gameId=emojis`。SDK 1.1.0 没有这个接口，没有假装那份收藏已同步。服务器表情只用新的 emoji 分组接口。
- 没有本地图片文件上传。SDK 表情只收 URL。选「仅插入」时只改输入框。
- 没有做设置里的网易云播放列表。
- 没有拉 `music.163.com/api/song/detail` 补歌手名。页面的 `connect-src` 不允许这个请求，卡片只用消息里已有的歌名和来源。

## 降级

- 天气或音乐字段缺失时显示摘要或歌名，不编造温度、城市或播放进度。
- 音频地址播放失败（包括当前 CSP 的 `media-src` 只有 `'self'` 和 `blob:`，外链音频可能被拦住）时显示「这一首没播起来」，不假装正在播。封面加载失败就去掉封面。这次没有改 `tauri.conf.json`。
- 本机屏蔽规则如果读失败，面板不允许保存，避免用空列表覆盖已有规则。
- 撤回后的重复消息会单独显示「已撤回」，不会从「也这么说」里直接抹掉。

## 设置页尚未挂载的入口

- 屏蔽规则和特别关心只在聊天室顶栏「屏蔽」里。设置页（`SettingsHost`）没有入口，这次也不能改那一侧。
